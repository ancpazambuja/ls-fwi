# Data dictionary — fast-fail AE trivial-inversion extract

Generated by `notebooks/data/extract_from_mlflow.py` (stdlib-only; provenance
script — re-run it to refresh). Source: MLflow experiment **`encdec.highres.inversion`**
(id 97, server `gr14sm02.ep.petrobras.com.br:31947`), extracted 2026-11-24.

**Vocabulary (per the inversion paper)**: *model* = ML model; *example* /
*velocity model* = a dataset item. Legacy identifiers keep the old wording
(`model_idx` = example index, `models_to_invert`, `inversion_per_model.csv`).

## The campaign in one paragraph

The AE loop's fast-fail study: for each of **4 refit models** — encdec 3×3
(seed 7, `6d115baa…`), encdec 5×5 (seed 79, `9247757e…`), encdec 7×7
(seed 571, `b01fdd28…`), transencdec 5×5 (seed 571, `32409900…`) — run
**trivial inversion** (optimize the latent z so `Generator(z)` matches each
true target model; model-space MSE loss) over a full factorial:
**4 latent inits × 5 lrs × 4 epoch budgets** = 80 configs per refit model.
Each run inverts **the SAME 3 target models**: the hardcoded inverted test
indices `[1, 10, 20]` (`task_processing.py: models_to_invert`), hand-picked
deliberately difficult examples from the refit's test set. The refit's 10%
MCCV holdout (100 examples; 900/100 split of the 1000-sample dataset) is
logged as context (`_x_test_indexes`), not the inversion target set. All
sweep runs share `lr_scheduler=cosine_annealing_wr` and `patience=300`.
`latent_init=trained` = the latent of a **randomly chosen training-set
example** (an in-distribution manifold point) — *not* the encoder's latent
of the target; the example is chosen by the same seed that controls the
split.

## Run lifecycle and cleaning (standing rule, user 2026-11-24 — valid forever)

**Standing rule**: the user plays with the code before real experiments,
so obsolete/wrong runs happen; they are deleted from MLflow before
results are taken, and test runs worth keeping are RENAMED to
distinguish them from final experiment runs. **All searches and
extracts for results use ACTIVE runs only — deleted runs are never
used as results** (they may remain in MLflow; the extractor's default
is `--run-view-type ACTIVE_ONLY`).

This campaign's history: it originally held 460 runs; a manual UI
cleanup soft-deleted 137 (all 68 `50-samples` debug runs, all 24
param-less early-launcher runs, all 44 duplicate re-run losers, and the
200-ep probe), leaving 323 active. The extract (ACTIVE_ONLY) contains:

| `group` | runs |
|---|---|
| `sweep_full_samples` | 320 — the complete 4×5×4 grid × 4 refit models |
| `tst_sanity` | 3 (deliberately kept; not part of the sweep) |

`kept_in_clean_set` is True for all 320 (one run per combo — the
duplicate re-runs, now deleted, were numerical replicates: same latent
init, measured spread 0 except at the lr=1.0 batch switch of Nov 12,
15:26–15:45 local; see docs/refactor-plan.md). The 320 active grid
runs are **run-identical** to the analysis set (verified against the
server).

## `runs.csv` (324 lines; one row per run, ACTIVE runs only)

  `start_time_iso` (**UTC**; cluster local time = UTC−3), `start_time_ms` —
  identity.
- `group`, `kept_in_clean_set` (True for all sweep runs — one run per combo
  in the active view), `has_valid_metrics` — cleaning flags.
- `combo` — `refit|latent_init|lr=<lr>|ep=<epochs>` (sweep runs only).
- `refit_short`, `arch_family` (encdec/transencdec), `kernel` (3/5/7),

- `latent_init`, `lr`, `max_epochs`, `lr_scheduler`, `patience`, `model_size`

- Final metrics (MLflow "latest value" = **final state at schedule end**):
  `inversion_{mse,mae,ssim}_{mean,min,max,std}_test_set` — mean/min/max/std
  over the run's **3 inverted targets** ([1, 10, 20], hand-picked difficult

  those specific examples — they are NOT a 100-example difficulty survey.
- `train_loss` — final optimization loss; `dur` — logged duration (**unit

## `train_loss_per_example.csv` (396,000 rows; 320 runs × 3 examples)

- `run_id`, `combo`, `refit_short`, `latent_init`, `lr`, `max_epochs` — join keys.
- `model_step` (0/1/2), `model_idx` (1/10/20) — which target example the
  trajectory belongs to (legacy `model` wording = example).
- `step`, `value` — epoch step and loss of that example's own trajectory.

**Why segmented**: a run's `train_loss` metric interleaves THREE
trajectories — the processing loop logs the history once per target
example, under the same metric key, with steps restarting per example.
Without segmentation there are 3 values per step and convergence plots
are unreadable. The extractor sorts the history by timestamp and splits
at step restarts (all 320 runs segmented into exactly 3 trajectories).
**Caveat**: `step` is whatever the callback logged — not guaranteed
exactly one per epoch, and steps may repeat; for a clean curve take the
last value per step within (run, example). Each trajectory's loss is the
optimization objective for THAT example (model-space MSE against it), so
its final value ≈ that example's `mse` in `inversion_per_model.csv`.
**`train_loss` vs the reported `mse`** (checked 2026-11-24): the
trajectory's final loss and that example's final `mse` agree closely —
median relative gap +2.1%, positive in 893/960 cases — because the loss
is computed in *train* mode (dropout active in the generator) while the
reported `mse` is an eval-mode forward pass. A minority of runs deviate
strongly (down to −89%), consistent with batch-norm train/eval mismatch
on single-example batches (not yet verified). The plotted curves are
the optimization objective, not exactly the final prediction error.

**⚠ Update (2026-11-26) — the train-mode artifact is far larger than the
+2.1% tip**: the +2.1% only measures the trajectory's *last step*.
During the whole campaign the generator ran in *train* mode during the
latent optimization (dropout active, batch-norm batch statistics), so
the optimization objective was stochastic and every curve plateaus at a
**dropout noise floor** (~0.003–0.008) far above the representational
floor. Control experiment (`marmousi01_read_view.ipynb`, cells 10–12):
re-running the campaign's three targets with the same config but the
generator pinned to eval (the `GeneratorInversion.train()` override)
reaches **0.00011–0.00031** — 10× to 55× below the campaign's reported
eval MSEs (0.0033–0.0060) — and the example-difficulty ordering changes.
Consequences: all 320 campaign inversions are noise-floor-limited;
their recovery and gap numbers are pessimistic/filtered through this
artifact; any latent optimization must pin the generator to eval (the
fix lives in `GeneratorInversion.train()`).
**Schedule × mode interaction (2×2 in the same notebook, 2026-11-26)**:
the campaign's SGDR schedule (`CosineAnnealingWarmRestarts` T_0=68,
T_mult=2, eta_min=1e-6) is destructive only in combination with train
mode. With the generator pinned to eval, the campaign's own schedule
reaches the same floor as constant lr (0.00028 vs 0.00027 on pos 1);
in train mode it freezes the run at the noise floor (0.00532 vs 0.00050
with constant lr). The eval-mode pin alone — schedule untouched —
accounts for the full campaign-vs-fix gap (19.5×); after the pin, the
lr schedule is a free knob.

## `inversion_per_model.csv` (960 rows = 320 runs × 3 targets)

- Join keys: `run_id`, `combo`, `refit_short`, `arch_family`, `kernel`,
  `seed`, `latent_init`, `lr`, `max_epochs` (as in `runs.csv`).
- `model_step` (0/1/2), `model_idx` (1/10/20) — the target's position in the
  sorted `models_to_invert` list.
- `mse`, `mae`, `ssim` — that target's own scalars.
- Consistency (verified at extraction): per run, the mean of the 3 per-model
  `mse` values equals `inversion_mse_mean_test_set` exactly (0 mismatches /
  320 runs). Difficulty preview: model 10 is the hardest target (avg MSE
  0.0132 vs 0.0060 / 0.0073).

## `inverted_examples.csv` (12 rows = 4 refit ML models × 3 positions)

The identity of the three inverted target examples: `example_pos`
(1/10/20 — 0-based position in the refit ML model's cropped test split)
→ `dataset_example_idx` (the example's index in the 1000-example
dataset). Per seed: 3×3 (seed 7) → 921/741/891; 5×5 (seed 79) →
476/696/5; 7×7 and transencdec (seed 571) → 429/63/239 (shared split).
The SAME position is a DIFFERENT dataset example across seeds.

## `refit_per_example.csv` (396 rows = 4 refit ML models × 99 holdout steps)

The refit ML models' **per-example prediction quality** on their own
holdouts, recovered from the step-indexed `*_values` series (steps 0–98;
the 100th holdout example is missing from the logs — all inversion
positions 1/10/20 are present). Enables the difficulty-matched paired
comparison: the refit's prediction MSE for an example vs the inversion's
recovery of the same example. Cross-checked: the series mean/min/max
match the logged `mse_mean/min/max_test_set` exactly.

## `refit_baselines.csv` (4 rows)

The refit models' own test metrics on the **same 100-model holdouts**:
`mse_*`, `mae_mean`, `ssim_mean`, `train_loss`, `valid_loss`. This is the
baseline the inversion is compared against (refit MSE 0.00083–0.00117,
SSIM 0.89–0.91).

## Known caveats

1. **Final-state reporting**: every final metric is the state at schedule
   end; with `cosine_annealing_wr` that can be a peak-lr (hot) point.
   Best-so-far from the history is the honest comparison — quantified in
   the notebook (user-confirmed issue; to be fixed for final experiments).
2. The `*_values` columns in `runs.csv` are **not** aggregates: they are the
   per-model series, logged with `step` = position in the sorted
   inverted-model list (`log_evaluation_results`); the "latest value" that
   `runs/search` returns is just the last model's value. The full series is
   extracted step-by-step into `inversion_per_model.csv` (step t → the t-th
   smallest inverted index; `--models-to-invert`, default `1,10,20`).
3. Metrics are in the pipeline's logged (post-preprocessing) model space;
   if units matter, check `src/preprocessing/pipeline.py`.
4. `test_perc=0.1` for all sweep runs; the logged test-index lists have 100
   entries per seed — the `debug_50samples` name segment does **not** match
   the logged indexes (one reason they are excluded as debug runs).
5. **Difficulty mismatch**: all sweep runs invert the same 3 hand-picked
   difficult targets, while `refit_baselines.csv` is a mean over the
   100-example holdout — inversion-vs-refit comparisons are
   difficulty-mismatched and the gap is inflated. The fair form is a
   per-model paired comparison against the refit's metrics for
   [1, 10, 20] (final-experiments checklist).
