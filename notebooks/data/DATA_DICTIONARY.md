# Data dictionary — fast-fail AE trivial-inversion extract

Generated by `notebooks/data/extract_from_mlflow.py` (stdlib-only; provenance
script — re-run it to refresh). Source: MLflow experiment **`encdec.highres.inversion`**
(id 97, server `gr14sm02.ep.petrobras.com.br:31947`), extracted 2026-11-24.

## The campaign in one paragraph

The AE loop's fast-fail study: for each of **4 refit models** — encdec 3×3
(seed 7, `6d115baa…`), encdec 5×5 (seed 79, `9247757e…`), encdec 7×7
(seed 571, `b01fdd28…`), transencdec 5×5 (seed 571, `32409900…`) — run
**trivial inversion** (optimize the latent z so `Generator(z)` matches each
true target model; model-space MSE loss) over a full factorial:
**4 latent inits × 5 lrs × 4 epoch budgets** = 80 configs per refit model.
Each run inverts the refit model's **100-model test set** (its 10% MCCV
holdout, seed-matched; 900/100 split of the 1000-sample dataset). All sweep
runs share `lr_scheduler=cosine_annealing_wr` and `patience=300`.
`latent_init=trained` = the latent of a **randomly chosen training-set
example** (an in-distribution manifold point) — *not* the encoder's latent
of the target.

## Cleaning policy (user-confirmed 2026-11-24)

| `group` | Meaning | Count |
|---|---|---|
| `sweep_full_samples` | parameterized, full-samples, non-`tst` runs — the sweep | 365 |
| `debug_50samples` | `50-samples` in name — debugging runs, **skip** | 68 |
| `tst_sanity` | `tst__inverting_on_train_dataset…` — sanity (train-split targets) | 3 |
| `param_less` | no logged params (earlier launcher generation), kept for the record | 24 |

Within `sweep_full_samples`, per combo keep the **LAST** run (by start time)
unless it lacks a valid final MSE → `kept_in_clean_set=True` for **321**
combos (320 grid + 1 exploratory `trained|lr=1.0|ep=200`); the other **44**
are duplicates, flagged `False` (they remain in MLflow — the `random`-init
duplicates are distinct latent draws, relevant to the ADR-0002 J-draws
protocol). 460 = 365 + 68 + 3 + 24.

## `runs.csv` (461 lines; one row per run, ALL runs)

- `run_id`, `run_name`, `status`, `start_time_iso`, `start_time_ms` — identity.
- `group`, `kept_in_clean_set` (True/False/"" — only sweep runs get a value),
  `has_valid_final_mse` — cleaning flags.
- `combo` — `refit|latent_init|lr=<lr>|ep=<epochs>` (sweep runs only).
- `refit_short`, `arch_family` (encdec/transencdec), `kernel` (3/5/7),
  `seed` (7/79/571) — refit-lineage columns.
- `latent_init`, `lr`, `max_epochs`, `lr_scheduler`, `patience`, `model_size`
  (parameter count), `test_perc` — sweep parameters (empty for `param_less`).
- Final metrics (MLflow "latest value" = **final state at schedule end**):
  `inversion_{mse,mae,ssim}_{mean,min,max,std}_test_set` — mean/min/max/std
  over the run's 100 test models. `min/max/std` quantify the per-model
  difficulty spread (easy models invert much better than hard ones).
- `train_loss` — final optimization loss; `dur` — logged duration (**unit
  not verified**).

## `train_loss_history.csv` (396,601 rows; clean kept runs only)

- `run_id`, `combo`, `refit_short`, `latent_init`, `lr`, `max_epochs` — join keys.
- `step`, `value` — MLflow step counter and logged loss.

**Caveat**: `step` is whatever the callback logged — it is **not guaranteed
to be exactly one per epoch** and steps may repeat (multiple rows per step).
For a clean curve: sort by `step`, take the last value per step. The loss is
the optimization objective itself (model-space MSE against the 100 targets),
so `train_loss` ≈ `inversion_mse_mean_test_set` at every point; the final
`value` should match `runs.csv`'s `train_loss`.

## `refit_baselines.csv` (4 rows)

The refit models' own test metrics on the **same 100-model holdouts**:
`mse_*`, `mae_mean`, `ssim_mean`, `train_loss`, `valid_loss`. This is the
baseline the inversion is compared against (refit MSE 0.00083–0.00117,
SSIM 0.89–0.91).

## Known caveats

1. **Final-state reporting**: every final metric is the state at schedule
   end; with `cosine_annealing_wr` that can be a peak-lr (hot) point.
   Best-so-far from the history is the honest comparison — quantified in
   the notebook (user-confirmed issue; to be fixed for final experiments).
2. The `*_values` columns are kept as logged but their **semantics are
   unclear** (a scalar, not the per-model list) — do not use them without
   checking the logging code first.
3. Metrics are in the pipeline's logged (post-preprocessing) model space;
   if units matter, check `src/preprocessing/pipeline.py`.
4. `test_perc=0.1` for all sweep runs; the logged test-index lists have 100
   entries per seed — the `debug_50samples` name segment does **not** match
   the logged indexes (one reason they are excluded as debug runs).
